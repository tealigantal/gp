- 自动刷新降级 run
  - `tool_registry.ensure_recommendation()`：若复用的 run 满足任一条件（items 为空、`degraded=true`、`tradeable=false`、`run_gating.decision!=allow`），自动执行一次 refresh，避免持续复用低质量结果；在响应中回传 `refresh_reason`（如 `auto_not_tradeable`）。

- AkShare 快照验证（本机）

## 仍存在/潜在问题与建议方案

- 会话复用旧消息：
  - 旧对话中的历史“no_trade”卡片与英文兜底文本仍会在 UI 中显示；解决：新建会话验证或提供“清空会话”入口；也可在前端对旧 `no_trade` 卡片做条件隐藏。

- 金融意图追问时的工具必调用：
  - 某些追问（如“这是什么/为什么是这几支”）可能只走 `chat` 工具，未落地 `ensure_recommendation/resolve_reference/explain_selection_set`，导致“symbols_out_of_scope”报错。
  - 建议：
    - 将含 6 位代码/“推荐/策略/第几只/这只/为什么/是什么”等关键词的回合强制要求调用非 chat 工具；
    - 在校验允许集合中并入 `session_state.active_symbols`，降低“追问未调用工具”时的误报。

- 可交易门槛仍可能触发：
  - 与“非交易日”无关的真实门槛（候选规模/执行性/主线硬限制等）仍会导致 `tradeable=false`；若需要更宽松策略，可调：`GATE_MIN_ACTIONABLE_RATIO`、`GATE_MIN_EXEC_SCORE_MEAN`，或关闭主线限制 `GP_RESTRICT_MAINLINE=0`。

- AkShare 性能与稳定性：
  - `sina` 路由全量抓取耗时偏长；建议配置：`AK_SPOT_PRIORITY=sina,em`，`AK_SPOT_REFRESH_TTL_SEC=30`，`AK_SPOT_DISK_TTL_SEC=600`，并注意网络连通与限流问题。

- 统一错误展示：
  - 目前已将“不可交易/校验失败”改为直接报错文本；建议前端对错误态增加显式样式（如红色 Banner/气泡），并允许“重试/刷新”快捷操作。
