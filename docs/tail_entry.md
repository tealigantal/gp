# 尾盘入场判断

当前实现：`SinaMinuteProvider → entry_evidence → EntryService → EntryAssessment`。
worker、ConversationService 的工具循环和卡片读取同一结果；原计划、评分和排序不变。

## 数据与时间

仅请求相关股票与沪深300的新浪原生五分钟线，原始字段为不复权价格、股数及真实成交额。请求8秒超时，无重试/备用源。现有午盘接口也使用该传输，删除 AKShare 分钟包装器中的备用路径以及 close×volume 伪造成交额。

交易日历来自仓库现有 calendar。14:35开始准备，14:57停止新建仓确认。先截断到判断日、判断时刻之前已闭合的五分钟线，然后检查顺序、重复、OHLC、单位和连续最近30分钟。最新闭合边界允许落后一根五分钟线，例如14:40可以使用14:35，不能使用14:30。尚未取得盘中发布延迟的现场验证；该边界不是供应商SLA。

保留判断、证据截止、实际获取和完成时间。`historical`实验不显示当前有效建议，计划晚于目标时间时明确只是链路实验。历史和实时结果、刷新状态分开，读取前次结果限定不晚于判断时间。

## 证据和建议

代码计算15/30分钟收益、最近7根收盘/高低点、相邻15分钟成交量比、当日开盘以来收益、真实VWAP及相对位置变化、同窗口基准收益、计划区间位置和止损事实。不存在尾盘分数。成交量比不命名为市场“量比”；缺少真实成交额或全天截至当前的完整样本时不计算VWAP，基准缺失只记局限。

模型使用用户当前配置。正式输出为 `action/trend/conclusion/reasons/evidence_fields/change`；`consider_entry`必须在原区间、未破止损、无明确禁止交易事实，并有支持的走势判断。`watch`是原日线观察属性，本身不否决入场。近期走弱可以降低当日入场建议，但新证据可以解除。明确的已验证同日停牌阻止分钟评估；空数据不能证明停牌。

股票和计划都采用不复权元价；近期变化以同日分钟线计算，不拿除权日开盘与前日收盘的差当作走弱。系统不擅自对历史买入区间做除权重算，未实现独立的公司行动调整服务。

新建仓和加仓分别缓存。本次不实现持仓规模/成本/风险预算引擎；仅声明买过一部分不能形成可靠加仓许可，必须保留该局限。

## 对话、持久化与页面

会话绑定原 publication，真实有序历史进入模型，工具包括读取计划、评估/刷新相关股票、读取前次评估和结构化回答。普通问候不取行情。“第一只/第二只”使用绑定计划中用户所见的入选顺序。最多6轮工具交互，每轮最多3个调用；没有中文关键词路由和反复改口。

首轮请求携带页面实际展示的publication_id，防止后台切换计划后指代错位；已有会话不随请求改绑。入场类respond的text必须为空，只显示所引用正式评估的结论、理由和change；历史解释显示带时间的已保存记录，不允许自由补充另一份当前建议。新核验的当日停牌事实会使仍在时效内的缓存评估立即失去当前有效状态。

同一计划/股票/场景/分钟证据仅保存一个正式结果，跨进程锁避免重复生成。现有 ContractStore 向前增加 entry_assessments 和 entry_attempts 表，不清空计划、会话或用户配置。失败记录保留根因，无规则/模板/其他模型替代。有效结果可复用；过期结果或失败后的旧买入判断不能作为当前结果。

`GET /api/entry/current?plan_id=...`按原计划读取；页面保留日线分数与排名，展示正式建议、走势、时间和理由。服务器返回有效截止，页面仅失效展示、不重新推导建议。报价可用与适合买入不同。
