# 尾盘人工盯盘叙述

## Purpose / Big Picture

让 GP 的唯一聊天链路把前一日日K计划翻译为用户在次日下午 14:45–14:56 可手工执行的尾盘观察清单。该能力不引入自动执行、实时数据抓取、候选重排或订单行为。

## Context and Orientation

- 生产路径为 `ConversationService._narrate()`；旧 narrator 已被物理删除，不能修改不存在的兼容路径。
- `RecommendationPlan` 已冻结入选候选、日线信号、入场区间、止损与止盈；LLM 只能解释这些事实。
- 当前运行时只提供有限现货可用性，不能作为 VWAP、量比、相对强弱或尾盘五分钟判定的来源。

## Plan of Work

1. 向唯一生产 prompt 注入固定的人工尾盘观察原则，并把日线信号类型加入同一份只读候选事实。
2. 明确 14:45–14:56 窗口、14:57 后不首次入场、区间/VWAP/相对沪深300/量比/五分钟形态/止损与放弃条件。
3. 禁止 LLM 把清单说成已经读取的实时事实或未来自动执行。
4. 只修改既有聊天测试，验证 prompt 与事实载荷包含该规则。
5. 更新产品、架构、契约、ADR、研究、进度与验证记录；重建受影响容器并通过真实可丢弃聊天确认。

## Decision Log

- 用户明确选择提示词式人工盯盘；不添加实时自动执行数据源。
- 固定阈值属于用户可见的叙述规则，不得被描述为模型已确认的行情数值。

## Validation and Acceptance

现有聊天合约测试必须证明：生产 prompt 含人工尾盘规则、候选事实包含日线信号、规则要求量比 1.3 且禁止编造实时指标。完整后执行编译、默认后端测试、Compose 检查、受影响服务重建和真实 `/api/chat` 验证；验证会话须删除。

## Idempotence and Recovery

变更只影响内存中的 LLM 提示词与文档，不写入推荐、运行时、市场日账本或会话 schema。回退为恢复此前 prompt；不需要数据库迁移或数据清理。

## Interfaces and Dependencies

HTTP 形状、推荐计划、运行时、发布和聊天持久化接口不变。外部依赖仍只有现有 LLM 服务；没有新增行情、券商或订单依赖。

## Outcomes & Retrospective

已完成：真实生产 narrator 而非已删除的旧模块现在能够将冻结日K计划解释为用户可自行执行的尾盘盯盘清单。没有把手工规则伪装为实时数据或自动执行。保留的风险是规则尚未作为自动策略做历史统计验证；这符合本次用户明确选择的人工决策辅助边界。
