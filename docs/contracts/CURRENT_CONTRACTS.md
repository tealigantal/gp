# Current Contract Kernel

GP has one recommendation lifecycle.

1. `RecommendationPlan` is an immutable decision version from the Adaptive Decision Engine. A base plan binds the session, completed daily evidence, complete candidate universe, policy state, and producer revision. An optional lunch-derived plan may retain that full evaluated scope while reranking only the base plan's frozen Top-30 from one exact, complete 11:30 five-minute batch; it is a new plan and never mutates the base plan.
2. `RuntimeObservation` is immutable intraday execution evidence for exactly one plan. It may only report symbols already evaluated by that plan.
3. `RecommendationPublication` is the only product projection. `PublicationService` alone constructs and commits it from a plan plus an optional runtime observation.

`PlanService` resolves the target before selection. A session before or during trading uses the current session and the latest completed daily evidence. After close, a pending daily bar yields an explicit pending state; a completed daily bar targets the next open session. The base plan identity is independent of polling time. A lunch-derived identity additionally binds the base plan ID and normalized closed five-minute content through the existing producer and policy identity fields.

The lunch batch is atomic: every frozen Top-30 symbol plus CSI300 must contain the exact 24 closed bars from 09:35 through 11:30 for the same session. Collection starts no earlier than 11:32 to avoid accepting an upstream row at the instant its label first appears. Any missing, duplicate, unordered, null, mixed-session or unclosed input means no lunch plan and no current-publication switch. A lunch plan must be published with its 11:30 `RuntimeObservation`; the lunch market gate remains deny. Existing conversation sessions keep their first publication, while a new session may bind the latest lunch publication.

The product database owns `recommendation_plans`, `runtime_observations`, `recommendation_publications`, `current_publication`, `sessions`, `turns`, and `claims`. The separate operational ledger owns frozen raw/expected universe counts, exact-date coverage and per-symbol no-bar evidence; it never becomes a recommendation or chat source. A daily coverage denominator may exclude a symbol only for a fresh same-session all-zero spot row or a verified official suspension fact. The latter must bind the exact symbol and target date, a pre-open CNINFO disclosure, a verified exchange listing, PDF text explicitly saying that the target date opens suspended, and a document digest. Any missing/late/ambiguous proof remains a coverage failure.

Public reads are `GET /api/recommendation/current`, `GET /api/conversations`, and `GET /api/conversations/{session_id}`. `DELETE /api/conversations/{session_id}` removes exactly one conversation plus its cascaded turns and claims; it never deletes the bound publication, plan, runtime, or another session. Deleted session IDs are tombstoned so a delayed chat request cannot recreate them. The conversation reads expose canonical `ConversationSession` and ordered `ConversationTurn` records; they do not recreate old Book, diagnostic, or run projections. Health reports publication lineage and historical runtime fields, plus two server-clock projections: `market_now` describes the already published plan's current relation and execution permission, while `next_plan_target` describes the independent target session, required daily evidence, recovery coverage and publication state. `ready_to_publish` means the required daily evidence is complete but a new publication does not yet exist; UI and narration must say exactly that and must label any displayed candidates as the prior complete plan. A completed required run may create the next-session base plan from 15:20 through the next open session's 09:30, including an overnight recovery completion. An expired current plan never means that tomorrow's plan is forbidden or absent. Only these projections may support a current-time or next-session user claim. The LLM may route and narrate only publication-bound evidence; it cannot select, rerank, or change values.

The next-session base-plan window is enforced twice: before full-market generation and immediately before its publication. A calculation that starts before 09:30 but finishes afterward may remain as an immutable unpinned audit plan; it cannot move `current_publication` during trading.

After a daily source is ready, its isolated market-run child continues through every not-yet-attempted 100-symbol batch, persists exact-date coverage, and heartbeats its lease after each batch. There is no whole-market wall-clock cutoff: source request timeouts and bounded routes contain an individual request, while retry is reserved for the unresolved residue after a complete persisted pass. A healthy scan may not be interrupted merely because it has already run for an arbitrary number of minutes. Exact readback remains full-universe evidence, but its query uses the indexed target-date range and the ledger mutates only the batch that was just observed.

`POST /api/chat` is the sole narration entry. Before LLM prose, `ConversationService` computes an answer-time projection from the actual Shanghai clock and the bound publication: current phase, execution permission, plan-session relation, daily-evidence date, plan generation/publication times, latest RuntimeObservation as a historical snapshot, and the independent next-plan target with read-only recovery state. The projection does not mutate a publication. It is the only authority for phrases such as “current”, “can execute”, “post-close”, or “next-session”; LLM prose that conflicts with it is not persisted. No alternate narrator, legacy tool router, or legacy payload contract may be restored.
