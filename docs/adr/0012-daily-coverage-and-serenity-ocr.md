# ADR 0012 — 精确日线覆盖与受限 Serenity OCR

- **Status:** Accepted
- **Date:** 2026-07-24

## Context

日线刷新把任意非空历史响应算成成功，并用多数日期及 99.9% 阈值判断完整，导致目标日尚未齐备时反复全市场扫描。Serenity 的 `pypdf` 快路径无法读取扫描公告，宽泛的“修订”标题又会下载不能产生有效事实的法律文件。两类问题都必须在不缩小全市场承诺、不改变公开合同和不弱化固定 0%/3% 原子门禁的前提下解决。

## Considered Options

1. 继续容忍少量缺失并把空响应当停牌：实现简单，但会按数据可得性偏袒股票。
2. 增加数据库表和公开诊断字段：审计直观，但会制造不必要的迁移和接口风险。
3. 用同日新鲜 spot 证明无 bar、精确目标日 100% 覆盖，并在现有 Serenity 文档 JSON 中加入受限 OCR 审计元数据。

## Decision

选择方案 3。原始主板全集不缩小。只有与所需日线目标日相同、未陈旧且字段完整的 spot 行，同时满足前收盘为正和当日价格/成交全零，才从目标日覆盖分母排除。非空返回与目标日存在分别计数，计划完整必须达到目标可交易全集 100% 精确日期覆盖。

PDF 先经与受支持事实事件族一致的标题分类和 `pypdf` 文本提取。只有结构有效但零有效文本的相关 PDF 才用 PDFium 逐页渲染并交给 Tesseract `chi_sim+eng`；页数、像素、DPI、字符、单页和总时间都有硬上限。身份、主题、置信度或方向/数字复核失败使整个目标批次为 0%。新逻辑使用 `serenity_fixed_batch_3pct_v2_ocr` 身份。午盘计划继续继承基础计划当时已绑定的 Serenity 结果。

## Rationale

同日明确无交易把停牌与来源失败分开，精确日期覆盖避免旧数据伪装成完成。受限 OCR 提升官方扫描公告可用性，而标题预筛选和二次校验避免无关文档或识别错误进入数值权威。现有摘要、JSON 和不可变计划足以绑定新语义，无需 schema 或公开接口迁移。

## Consequences

- 无法证明同日停牌时继续 fail closed，宁可暂不可用也不缩小全集。
- OCR 增加镜像体积和 worker 子进程 CPU 峰值，但不进入 API/chat 请求路径。
- 一个相关文档失败仍使整批 Serenity 为 0%，基础推荐继续运行。
- v1 批次继续可读但不会被 v2 目标复用；晚到 Serenity 批次从下一份基础计划生效。

## Migration

无数据库、ContractModel 或 HTTP 迁移。构建镜像时增加原生 OCR 和固定 Python 依赖；部署需另行授权。

## Rollback

回滚代码和镜像即可。现有 v1/v2 追加记录保留，旧版本忽略未知 JSON 元数据；OCR 缺失自动走整批 0% 而不是元数据猜测。
