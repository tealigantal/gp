# ADR 0013：持久化市场日编排与停机自愈

## Status

Accepted — 2026-07-27.

## Context

原 core worker 将每日刷新、计划生成、午盘、运行时和恢复拼接在一分钟循环中。午盘是否已生成曾错误影响下午全市场日K刷新；计划生产者也会自行采集与发布，导致不完整日K计划能够推进 `current_publication`。这不是 `history.db`、`agent.db` 或 Serenity 数据的设计故障，而是编排和发布契约没有单一所有者。

## Decision

新增独立 `store/market_runs.db`，由 `MarketDayOrchestrator` 管理 daily run、股票级进度、租约、恢复检查点和午盘一次性状态。每日计划仅从已完成 run 的冻结分母和精确目标日覆盖读取；所有采集在 worker 及其日K子进程，API/聊天不再触发采集。完成前一交易日日K后，下一交易日的基础计划从 15:20 起即可生成，窗口持续到目标日 09:30；这条跨午夜窗口让停机恢复在夜间完成时仍能发布正确的下一交易日版本。

发布资格在 `PublicationService` 和 `ContractStore` 双重强制：候选范围完整、目标日日K存在且计划是 recommend 或 no-recommend 才能替换当前指针。恢复期间保留最后完整发布。无历史冻结分母的回补标记为 `reconstructed_current_universe`，只能修复日K，不能宣称历史全市场推荐。

## Consequences

- 容器跨日停机可按旧到新恢复，且重启不会重抓已覆盖股票。
- 完整扫描的边界是每个来源请求及其有限路由，而不是任意总时长；目标日覆盖查询走 `(query_id,item_time)` 索引，股票账本只更新刚处理的批次，因而不会在每批后重写整个冻结分母。
- 14:57 冻结、15:05 探测、15:20 全市场抓取与下一交易日基础计划窗口开始、11:32 午盘、盘中运行时和收盘 T+5 各有固定窗口；基础计划窗口跨午夜并在目标日 09:30 结束。
- 原有产品数据库与 HTTP 推荐/聊天/会话形状保持不变；health 增加只读恢复摘要。
- 新账本是运行事实，不是历史推荐事实；生产可观察性增加而存储边界不扩大。

## Rollback

回退镜像即可回到旧 worker；不删除或迁移 `market_runs.db`、`history.db`、`agent.db` 或 Serenity 证据。旧 worker 不读取新账本，因此回退不会损坏既有产品库，但会失去新自愈与发布门禁保障。
