# ADR 0014：唯一聊天叙述入口与回答时刻真相

## Status

Accepted — 2026-07-27.

## Context

GP 曾同时保留两个不兼容的叙述实现。`POST /api/chat` 使用 `ConversationService`，而一次名为“收盘后叙述修复”的提交只修改未接入的 `llm/narrate.py`。因此真实容器在 22:04 的聊天中，把 14:59 的历史 RuntimeObservation 写成当前收盘集合竞价，并把运行态发布误称为收盘后日线计划。

不可变 `RecommendationPublication` 必须保留其发布时的 RuntimeObservation；它不能也不应改写为回答时刻的状态。真正的问题是聊天没有单一时间事实所有者，也没有在持久化前拒绝与事实冲突的叙述。

## Decision

`ConversationService → LLMClient` 是唯一生产叙述入口。服务在每次回答时计算并先展示确定性的时间与执行结论：回答时刻、当前市场阶段、当前是否可执行、计划交易日与回答时刻的关系、日线证据日期、计划生成/发布时刻、历史盘中观察和只读恢复状态。

LLM 只解释候选事实，不能重新定义任何时间、执行或计划时态结论。服务会对关键冲突进行一次同链路重生成；仍冲突的文本不会保存为 ConversationTurn。同一投影通过非破坏性 `health.market_now` 和 `health.next_plan_target` 字段供网页使用：前者只描述当前发布计划，后者独立描述下一交易日目标及其日K完整性；历史 RuntimeObservation 字段不得再被页面解释为当前时刻。`llm/narrate.py`、专属旧 payload/trace 代码和无入口 `tools/legacy/` 被物理删除，不保留兼容分支。聊天与 health 读取市场日账本时必须只读，不得初始化账本或触发工作。

## Consequences

- “最后盘中观察”与“回答时刻”不再混淆；计划已结束时只能回顾，同时必须单独说明下一交易日计划是已发布还是仍在等待所需日K，不能把旧计划过期表述为没有明日计划。
- 历史运行态与不可变发布继续保留，可用于回顾，但不再伪装为当前市场事实。
- 聊天失败关闭而不是持久化一条时间错误的 LLM 文本。
- 无入口的双 prompt、旧工具路由和旧两阶段叙述验证不再制造假修复或假健康状态。

## Rollback

回退镜像或 Git 提交可恢复之前的源码；本次不迁移或删除任何计划、发布、会话、日K或 Serenity 数据。不会恢复旧叙述模块作为并行路径。
